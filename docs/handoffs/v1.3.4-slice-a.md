## 实现与保护

任务更新在修改前保存原任务 XML/平台定义、启用状态、原登录身份、设置和本地任务记录。
注册、注册后核对、辅助结果返回、任务记录与设置写入失败均进入恢复。原先有任务时恢复原任务；
原先没有任务时只删除本次创建的同名任务，拒绝删除其他文件夹随后创建的任务。
Windows 仍仅提升任务小工具，任务保持原用户 Interactive / Limited，不提升应用。

事务记录及原始字节留在便携文件夹的 `data/`。恢复未完成时保留记录与任务快照，返回真实错误，
界面显示恢复未完成并禁用更新重试；独立新进程仍拒绝后续提醒写入。成功提交或确认恢复后才结束记录。
不读写 SMTP 授权码，不改变发送账本；更新/迁移不执行首次检查。首次主动启用仍保留原有行为。
数据/提醒状态/设置 schema 保持 8/2/3，接口为兼容扩展；未修改启动器、邮箱接入和导入格式。

macOS 保存 plist、加载及停用状态；更新和恢复的 bootstrap 临时抑制 RunAtLoad，避免立即执行 worker，
随后恢复磁盘定义供下次登录使用。已有停用或未加载的任务保持其状态。此路径仅完成模拟验证。

## 待验证与处理边界

1. macOS 原生环境不可用：需在原生环境验证文件替换、任务加载/停用状态、恢复失败及不立即执行。
   模拟 launchctl 不证明原生行为；未请求推送或 CI 发布工作来替代此限制。
2. Windows 普通会话注册被系统拒绝，已通过系统权限提示运行限定的原生测试，核对注册任务仍为
   原用户 Limited。真实 UAC 取消、标准用户输入另一管理员凭据未覆盖；取消仅有 Node/UI 模拟。
3. 未完成恢复不会自动重放，也没有新增一键恢复入口。保留当前及旧版文件夹和完整 `data/`，
   先停止相关更新，按快照核对实际任务及每个目标文件；只有确认全部恢复后才能移走未完成记录。
   不应只删除 `.scheduler-update.json` 来解除保护，不承诺磁盘故障都可自动恢复。
