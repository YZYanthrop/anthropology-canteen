测试 SHA `79d0efab2800aee0b30ba8f768d93cba001624c6`；

## 根因与影响

发布源码 reminder-scheduler.mjs:429–435 的 macJobDisabled 只接受 true/false。
真实 launchctl print-disabled gui/501 为测试唯一 label 返回 `=> disabled`，独立 oracle 将其判为 true，
产品却按 false 继续。记录的是未经改写的真实返回，未模拟 launchctl 或替换正式包实现。

| 原生前态 / 操作 | 预期 | 两架构实测 |
| --- | --- | --- |
| 已加载且停用，查询状态 | disabled 且有 job-disabled | installed=true、definitionValid=true、status=current、reasonCodes=[] |
| 未加载且停用，查询状态 | job-unloaded 和 job-disabled | 状态 disabled，但只有 job-unloaded |
| 已加载且停用，正常更新 | 成功更新并保持原 loaded/disabled，worker 不立即执行 | bootout 后 bootstrap 原生 code 5，恢复 bootstrap 再失败；原任务不再加载 |
| 停用任务，写入后阻挡 plist 恢复 | 保留真实前态和恢复资料，提示恢复未完成 | 提示与 journal 保留正确，但 journal.mac.disabled=false，实际前态为 true |

原生 bootstrap 诊断为 `Bootstrap failed: 5: Input/output error`。
产品抛出 SCHEDULER_ROLLBACK_FAILED、恢复未完成，状态 recovery-required，留下 prepared journal 和原 plist。
虽然错误没有被隐瞒，恢复机会也有保留，但原任务加载状态未恢复，停用快照错误。没有提权执行诊断提示建议的 root 操作。

## 八个失败检查与覆盖缺口

- A-loaded-disabled-none：不注入任何故障仍失败，是 A 的最小复现。
- C-loaded-disabled：只读真实状态即误报 current，是 C 的最小复现。
- C-disabled：停用原因遗漏，不能把“因未加载而显示停用”当正确解析。
- A-disabled-recovery-obstruction：注入及真实 plist 阻挡到达，错误提示和 journal 保留有证据；
  disabled 快照断言失败后，后续重复/新进程阻写断言未执行。
- A-loaded-disabled-marker-write、A-loaded-disabled-settings-write、A-loaded-disabled-recovery-obstruction：
  原生更新更早失败，injected=false；不声称覆盖了指定写入或恢复阻挡路径。
- A-loaded-disabled-post-registration-query：injected=true，但原生 bootstrap 先失败，注入发生于恢复查询；
  不是“注册成功后的检查失败”验收，原 loaded 状态也未恢复。

另四个 A-disabled 通过检查只说明最终状态/字节断言通过；它们的产品 prepared snapshot 仍为 disabled=false。
不能据通过数量缩小根因影响，也不能把其他状态通过的恢复保护推广至这些未到达断言。
C 编译 UI 对合成 current 会显示“邮件提醒正在运行”，但本轮没有真实系统至 UI 的端到端用例，二者证据分别保留。

## 可重复的最小场景

在普通 macOS 用户且 GUI launchd 会话可用的隔离环境中，使用上述测试提交，源码目录必须是精确 bb78dd9。
不得对用户已有 label 操作。脚本会生成随机唯一 label、manifest、合成 settings 和只写时间/计数的 worker。
用正式包内对应架构 runtime/bin/node 执行，不需要安装或构建产品。以下占位路径应指向新建的隔离临时目录：

```sh
"$PUBLISHED_NODE" packaging/macos/acceptance-v134/scheduler.mjs \
  --source "$EXACT_RELEASE_SOURCE" --scratch "$FRESH_UNIQUE_SCRATCH" \
  --report "$REPORT_DIR/scheduler.json" \
  --case A-loaded-disabled-none,C-loaded-disabled
```

正常结束或失败后都用相同 scratch manifest 核对清理：

```sh
"$PUBLISHED_NODE" packaging/macos/acceptance-v134/scheduler.mjs \
  --source "$EXACT_RELEASE_SOURCE" --scratch "$FRESH_UNIQUE_SCRATCH" \
  --report "$REPORT_DIR/scheduler-cleanup.json" --cleanup
```

本任务已经完成以上两类实际场景，不自动再执行；此命令是后续授权修复任务的复现入口。
证据在该运行两架构 artifact 的 evidence/scheduler/<case>/observation.json：
initialDisabledOracle.rawLine、productPreparedSnapshot、productStatus、productOperation.error/injected。
对应 original.plist / observed.plist / recovery-journal.json 仅含合成资料，保留 artifact 与本机 outputs，不提交 Git。
所有更新及恢复 fixture 的 worker 计数 0。

后续版本应覆盖真实 enabled/disabled 输出及不识别格式，修复后重验上述最小案例和受阻断言；
并核对停用覆盖项保存、原任务定义/加载状态恢复和无意外触发。本交接不等于批准实现或发布。
两架构 R2 精确任务/plist/进程均已清理；每架构仍保留 12 条 enabled override，未做用户全局配置清空。
