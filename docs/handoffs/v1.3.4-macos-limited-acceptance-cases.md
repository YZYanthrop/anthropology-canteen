## 解读边界

- `published-black-box`：未修改正式 ZIP 的校验、启动、页面、保存与服务进程重启持久化。
- `published-ui-synthetic-status`：未修改编译 UI、合成 API 状态；文案/按钮通过不代表真实系统至 UI 链路通过。
- `source-native`：精确发布源码调用真实 launchctl；worker 为独立离线夹具，不在正式包内替换实现。
- `source-injection-native-observer`：精确发布源码的注入入口和真实系统观察；recovery-obstruction 在注入写入失败后制造真实 plist 文件阻塞。
- `native-filesystem` / `source-native-system-fault`：真实 chmod 文件权限拒绝；后者的 launchctl 单任务 ACL 拒绝尚未执行。
- `source-injection`：源码故障注入、受控竞态或中断边界；B-process-interruption 确实 SIGKILL 子进程并启动新进程，合成锁龄前移 11 分钟，不代表整机重启。
- R2 的 A-loaded-disabled-marker-write/settings-write/recovery-obstruction 未到达指定注入点；A-loaded-disabled-post-registration-query 的注入发生在恢复查询阶段，不能算注册成功后检查失败通过。
- R2 中四个 A-disabled 通过项只证明其断言覆盖的最终状态/字节恢复；所留产品快照仍误写 disabled=false，缺陷没有消失。
- scheduler.final-cleanup-command 通过指精确任务、plist、进程及受管凭据清理；R2 每架构仍保留 12 条 enabled override，R1 旧 oracle 对 override absent 的结论无效。
- case 表保留 R1 原生通过项目；首次 19 失败及工作流零任务解析失败仍见主报告，不覆盖历史。
