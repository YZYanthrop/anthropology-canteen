# v1.3.2: usability and recovery

- Status: `In progress`
- Last updated: 2026-08-23
- Target version: `v1.3.2`
- Planning task: `方案 v1.3.2：可用性与恢复能力`
- Implementation branch: `codex/v1.3.2-ui-test-foundation`

This plan is approved for implementation as one prerequisite and three bounded,
sequential slices. It does not authorize pushing, tagging, packaging, publishing,
or starting more than one slice at a time.

## Problem and outcome

v1.3.1 strengthened data safety, identity evidence, and reminder reliability,
but several interface behaviors still make routine reading and recovery harder
than necessary. v1.3.2 will make article states understandable and reversible,
show real update health, keep core controls usable from the keyboard and on
narrow screens, and add focused UI regression coverage without adding an
account, hosted service, or new product architecture.

## Approved scope

### Prerequisite: focused UI interaction tests

- Add a jsdom component-test environment compatible with the existing
  React/Vite application and a separate UI-test command.
- Render the home page with deterministic local-data and API mocks as the first
  harness test; do not change product behavior in this prerequisite.
- Add the Slice A, B, and C interaction regressions to this suite as their
  behavior is implemented.

### Slice A: article state, recovery, and date correctness

- Add an `ignored` filter to the existing shared article list, with a visible
  ignored count and a restore action. Do not add a separate recovery page.
- Provide an immediate undo action after ignoring an article.
- Keep the main local-data schema at version 8 and add an optional,
  backward-compatible `articleArchive` keyed by article ID. Retain sanitized,
  uncapped display snapshots while an article is saved or ignored, and refresh
  those snapshots when newer copies appear in the feed.
- Backfill snapshots available in an existing feed on first load. If a legacy
  saved or ignored state has no recoverable metadata, show an explicit
  placeholder row that still lets the user restore or clear the state without
  editing JSON.
- Preserve saved, read, and translated state when an article is ignored;
  restoring clears only `ignored`. The saved count covers visible, non-ignored
  saved rows, while the ignored count covers every ignored row, including
  legacy placeholders.
- Add optional publication precision (`day`, `month`, or `year`) to feed and
  archived articles. OpenAlex, Semantic Scholar, and Crossref must record only
  the date precision actually supplied, and duplicate merging must prefer the
  most precise valid date.
- Treat legacy `YYYY-01-01` values without precision as year-only. Display and
  sort year/month/day values without claiming unknown components: known months
  and days sort descending, less precise records follow precise records in the
  same period, and article ID is the stable final tie-breaker.
- Count an item as published after the follow date only when its precision can
  establish that fact. A year-only item in the follow year, or a month-only
  item in the follow month, is not assumed to be new.

### Slice B: navigation, new-item actions, and update health

- Add one reset-to-overview action used by both the logo and a visible return
  control on scholar details. It clears the profile, active subscription,
  history mode, list filter, and search query before returning to the scholar
  overview.
- Show each scholar's count of followed-after, unread, non-ignored feed items
  and add a scholar-scoped mark-all-read action with deterministic state tests.
- Replace the focusable outer scholar card with a non-interactive article
  container and explicit native controls for viewing publications and marking
  items read; do not nest interactive controls inside `role="button"`.
- Extend feed coverage with subscription status (`success`, `partial`, or
  `failed`) and results for the OpenAlex, Semantic Scholar, and Crossref
  providers that were actually attempted. Provider absence must not be
  presented as an attempt or failure.
- Remove the hard-coded seven-bar activity chart. Show the last time data was
  successfully obtained, subscription success/partial/failure totals, and the
  failed providers. Keep a compact update-health summary visible when the
  desktop right rail is hidden.
- An all-failed refresh keeps the previous feed and successful timestamp and
  must not show a success notice. Partial degradation remains visible even
  when some records were returned.
- Keep scholar overview cards consistent while allowing essential status and
  actions to remain visible without fixed-height clipping.

### Slice C: reminder clarity, accessibility, and narrow screens

- Keep a normalized snapshot of the last saved reminder configuration and
  compare it with the form and pending credential input to derive dirty state.
- While dirty, do not label the edited form as saved or tested, and disable
  test/enable actions that would apply to the unsaved values. If an older saved
  schedule is still active, state explicitly that it continues to use the
  saved configuration.
- Require confirmation before discarding dirty reminder edits.
- Give the add and reminder dialogs initial focus, a focus trap, Escape close,
  and focus return to the opening control.
- Give notices a polite status live region and errors appropriate alert
  semantics. Replace visual match chips or other controls with no action by
  non-focusable semantic elements.
- At 820 px and below, keep search visible as a full-width second top-bar row;
  do not replace it with a hidden or icon-only entry point.
- Keep content-bearing metadata at least 11 px and form labels/control text at
  least 12 px while preserving the Source Han Serif visual system.

## Dependencies and implementation order

The order is fixed and sequential:

1. UI interaction-test prerequisite.
2. Slice A, including persistence and publication-date helpers.
3. Slice B, which depends on Slice A's state and date semantics.
4. Slice C, after the shared page interactions have stabilized.

Each step uses a separate short-lived `codex/` branch and handoff. The next step
must start only from a baseline where the previous step has been verified and
merged. These tasks all touch `app/page.tsx`, so they must not run in parallel.

## Compatibility and non-goals

- Version 8 local data without `articleArchive` or publication precision remains
  valid. Additive sanitization and backfill must preserve old subscriptions,
  follow dates, article states, translations, caches, and profiles on failure.
- Reminder delivery state stays independent from article read state.
- Windows and macOS continue to use the same app and portable-server
  implementation.
- This version does not add accounts, cloud sync, hosted notifications, paid
  infrastructure, academic providers, Google Scholar scraping, weak-evidence
  author merging, a full visual redesign, or an Electron/Tauri rewrite.
- A full WCAG audit and broad responsive/visual refactor remain candidates for
  v1.4.0.
- Publishing v1.3.2 is a separate task requiring explicit authorization.

## Acceptance criteria

- Saved and ignored items remain discoverable after refresh and restart, or
  appear as an honest legacy placeholder when old metadata is unavailable.
- Save, ignore, undo, restore, clear-state, and mark-read operations keep counts
  and visible rows consistent without losing unrelated state.
- Year-only and month-only works never claim fabricated date components;
  provider merging, same-period sorting, and follow-date comparisons are
  deterministic.
- Logo and detail return controls produce the same fully reset scholar overview.
- Scholar new-item counts and mark-all-read actions affect only that scholar's
  confirmed post-follow, unread, non-ignored articles.
- Update timestamps and coverage reflect actual subscription and provider
  outcomes. An all-failed refresh preserves the last successful cache and time.
- Editing a saved or tested reminder form clearly requires save and retest, and
  dirty edits cannot be discarded silently.
- Core search, article actions, notifications, and dialogs remain keyboard
  usable at desktop and narrow widths.

## Test and documentation plan

- Every implementation task runs `pnpm lint`, `pnpm build`,
  `node --test tests/*.test.mjs`, and the new UI-test command.
- Slice A adds deterministic persistence, schema-8 compatibility, orphan-state,
  state-transition, precision, and ordering tests.
- Slice B adds provider-degradation API tests plus DOM tests for navigation,
  counts, scoped mark-read, and update-health behavior.
- Slice C adds DOM tests for reminder dirty state, discard confirmation, focus
  trap, Escape, focus return, live feedback, and narrow-screen search presence.
- Slice A updates `docs/ARCHITECTURE.md`. User-visible slices update
  `CHANGELOG.md`; milestone completion updates `docs/PROJECT_STATE.md`.
- No packaging, launcher, or import-format version change is approved. Native
  platform packaging smoke is not required unless an implementation task finds
  that such a change is unavoidable; in that case it must stop for re-review.
