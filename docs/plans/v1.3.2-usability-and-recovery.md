# v1.3.2: usability and recovery

- Status: `Proposed`
- Last updated: 2026-08-23
- Target version: `v1.3.2`
- Planning task: `方案 v1.3.2：可用性与恢复能力`
- Implementation branch: `none`

This is a transition candidate, not an approved implementation order. It turns
the post-v1.3.1 audit into bounded slices so the next planning task can accept,
remove, or reorder them without reading the old conversation.

## Problem and outcome

v1.3.1 strengthened data safety, identity evidence, and reminder reliability,
but several interface behaviors still make routine reading and recovery harder
than necessary. v1.3.2 should make states understandable and reversible, show
real update health, and reduce UI regression risk without changing the product
architecture or adding services.

## Proposed scope

### Slice A: article state and date correctness

- Add a visible way to review and restore ignored articles.
- Make saved/ignored counts and lists consistent.
- Preserve exact publication dates when providers supply them; do not display
  January 1 when only a year is known.
- Add deterministic tests for state recovery, counts, date precision, and
  same-year ordering.

### Slice B: navigation and update visibility

- Make the logo reliably return to the scholar overview and clear detail
  filters; add a clear return path from scholar profiles.
- Show each scholar's new-item count and suitable mark-read action.
- Display the last successful refresh and provider/subscription coverage using
  real data; remove or replace the hard-coded seven-bar activity chart.
- Keep the scholar overview cards visually consistent without clipping
  essential information.

### Slice C: reminder settings clarity and accessibility

- Treat unsaved reminder edits as dirty; do not display saved/tested status for
  an older configuration after fields change.
- Provide clear focus handling, Escape close, focus return, and accessible live
  feedback for dialogs and notifications.
- Restore search access on narrow screens and raise unreadably small metadata
  text while preserving the Source Han Serif design.
- Remove non-interactive controls from the keyboard focus order.
- Introduce focused component/DOM interaction tests before broad UI refactoring.

## Non-goals

- Accounts, cloud sync, hosted notifications, or a paid server.
- New academic metadata providers or Google Scholar scraping.
- Automatic scholar merging from weak contextual evidence.
- A redesign of the entire visual language or an Electron/Tauri rewrite.
- Publishing v1.3.2; publication remains a separate authorized task.

## Compatibility and invariants

- Prefer no data-schema change. If ignored-item recovery needs metadata, it
  must be additive and preserve version 8 data on migration failure.
- Email reminder delivery state remains independent from article read state.
- Windows and macOS use the same app implementation.
- All current identity, local-storage, privacy, and blank-package rules remain
  unchanged.

## Acceptance criteria

- An ignored article can be found and restored without editing JSON.
- Counts match the visible state after save, ignore, restore, and mark-read.
- Year-only works never claim a fabricated day or month.
- A user can return from any scholar detail to a correctly reset overview.
- Refresh time and failures are based on actual feed coverage, not decoration.
- Editing a tested reminder configuration clearly requires save and retest.
- Core search and dialogs remain keyboard-usable at desktop and narrow widths.

## Test and delivery plan

- One implementation task and short-lived branch per slice.
- Slices A and B both touch page state and should run sequentially unless file
  ownership is separated first. Slice C should follow the test-harness setup.
- Each slice adds deterministic regression coverage and runs lint, build, and
  the full Node test suite.
- Final integration requires Windows portable smoke plus native macOS arm64/x64
  smoke if packaging or launcher inputs change.

## Decisions for the planning task

- Confirm whether all three slices belong in v1.3.2 or whether accessibility
  and responsive work should become v1.4.0.
- Decide whether “restore ignored” is a dedicated view or a filter in the saved
  view; prefer the smallest discoverable option.
- Approve the plan and update `docs/work/ACTIVE.md` before implementation.
