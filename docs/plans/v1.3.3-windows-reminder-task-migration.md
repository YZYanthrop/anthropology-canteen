## 实施结果

- 同一提醒身份始终使用同一个任务名；普通权限先原位更新，只有 Windows 拒绝时才启动受限小工具请求一次权限确认。
- 小工具保留原登录用户，并把任务注册为 `Interactive`、`RunLevel Limited`；应用、本地服务器和日常提醒不提升权限。
- 小工具在内部核对程序、提醒程序、工作目录、时间、用户和权限级别。只有核对成功才返回结果并写任务标记；取消权限确认时不改设置、授权码、发送记录或任务标记。
- 当前普通桌面会话也可能无权读取任务列表。此时状态接口说明无法自动核对，并只把最近一次已验证的任务标记作为显示依据，不返回本机路径或账户名。
- 不同任务名的旧任务没有自动删除路径。只能报告数量和不含个人资料的身份编号，由用户在 Windows 任务计划程序中核对。
- 完整结果和验证证据见 [Slice E 交接](../handoffs/v1.3.3-slice-e.md)。

## 用户问题与已确认事实

用户会看到什么：从旧版文件夹升级后，邮件资料已经保留，但点击“迁移到当前文件夹”时，
Windows 可能要求关闭应用，再以管理员身份启动整个程序。

为什么不方便：升级流程被打断，用户还会合理担心每次升级都新建一条后台提醒任务，
最终留下多条任务或重复发送邮件。

技术原因：Windows 计划任务记录了运行程序、提醒程序和工作目录的绝对路径。新版位于
另一个便携文件夹时，旧任务仍指向旧文件夹。当前任务名称由安装身份编号（代码中的
`installationId`）生成，
同一身份会使用同一名称，并通过 `Register-ScheduledTask -Force` 覆盖更新，因此正常迁移
不应增加任务数量；但是当前程序主要依赖文件夹内的任务标记，不能完整核对操作系统中的
实际任务。身份编号曾变化、用户重新配置或旧版本留下其他名称时，可能存在无法自动确认的
旧任务。普通权限被 Windows 拒绝时，现有界面只能提示以管理员身份重启整个应用。

本次规划时，当前普通进程无法列出本机计划任务并返回“拒绝访问”，因此没有声称本机
存在或不存在重复任务，也没有修改、注册或删除任何任务。

## 目标

1. 升级时只更新当前提醒身份对应的任务；重复迁移、重复点击和重复启动保持一条任务。
2. 需要更高权限时，只提升负责检查和更新任务的小工具，应用页面和本地服务器不以管理员
   身份运行，也不要求用户先关闭整个应用。
3. 更新后核对任务确实指向当前文件夹、当前 Windows 登录用户，并继续以受限权限运行。
4. 只清理能够唯一证明属于本次迁移来源的旧任务；来源不明确时不删除，并用普通中文说明。
5. 失败、取消权限确认或验证不通过时，保留原任务、设置、授权码和发送记录，不留下半套状态。

## 范围

### E1：任务身份、检查与重复保护

- 将“文件夹内任务标记”和“Windows 中的实际任务”分开检查。状态至少区分：
  当前文件夹已安装、旧路径待更新、任务缺失、发现来源不明确的旧任务、无权检查。
- 继续使用当前安装身份生成确定的任务名称。相同身份的注册必须更新同名任务，不创建新名称。
- 验收目标是“当前提醒身份只有一条任务”，不是强制整台电脑只能有一条；用户有意保留的另一份
  独立便携副本可以拥有自己的提醒身份和任务。
- 核对任务操作中的运行程序、提醒程序、工作目录、触发时间、登录用户和运行权限；界面与接口
  不返回完整个人路径、用户名、邮箱或其他敏感内容。
- 若保存的旧任务名称与当前名称不同，只在名称符合本产品格式、任务操作明确指向选定旧版文件夹，
  且旧版与当前提醒身份能够唯一对应时，才把它列为可清理对象。
- 不能仅凭 `Anthropology Canteen` 名称前缀批量删除任务。其他身份、其他文件夹或多个候选一律
  保留，并提示用户人工确认。

### E2：只提升任务小工具并完成原位更新

- “迁移到当前文件夹”先以普通权限检查；如果 Windows 拒绝更新，只启动一个范围受限的
  PowerShell 小工具并显示标准 Windows 权限确认（UAC），不重新启动整个应用。
- 提升前由普通进程确定目标 Windows 登录用户；提升后仍为该用户注册 `Interactive`、
  `RunLevel Limited` 的任务，不能因为使用了另一管理员账户的凭据而把提醒注册给管理员账户。
- 传给小工具的参数只包含任务定义所需的名称、时间和经过验证的本地路径，不包含授权码、
  邮箱密码或邮件正文。脚本必须拒绝产品目录之外的提醒程序、非法任务名称及异常路径。
- 优先用同名任务的强制更新完成原位迁移。新任务验证成功后，才处理唯一确认的旧名称任务；
  旧任务清理失败时，不得把两条任务都当作成功状态。
- Windows 权限确认被取消时，显示“没有更改后台提醒任务”，页面保持可继续操作；不得发送邮件、
  运行立即检查或修改已保存的授权码。
- 更新成功后重新读取系统任务并确认只存在一条当前身份任务，且路径指向当前文件夹；然后更新
  文件夹内任务标记。验证失败时恢复可恢复的旧定义，并把提醒保持在明确的未迁移状态。

### E3：界面说明与保守清理

- 把操作名称说明为“更新后台提醒到当前文件夹”，并提前说明可能出现一次 Windows 权限确认，
  日常使用不需要管理员权限。
- 成功后显示“后台提醒已更新到当前文件夹”，并说明重复操作不会增加任务。
- 发现无法唯一确认的其他任务时，显示任务数量和不含个人路径的识别信息；本阶段不提供一键
  全部删除。只有用户明确选择且再次核对后，才允许清理单个已识别旧任务。
- 若安全实现单个选择清理会明显扩大界面或权限范围，v1.3.3 只报告并给出 Windows 自带任务
  管理器中的人工检查步骤，把任务管理界面留到 v1.4.0。

## 数据与兼容性

- 主数据格式保持 8、提醒状态保持 2、设置保持 3。
- 保留现有 `credentialConfigured`、`credentialStatus` 和提醒设置兼容字段。
- 不改变 Windows 加密授权码文件，不读取或转换明文；不改变 macOS 钥匙串和 LaunchAgent 行为。
- 不改变邮箱服务接入、发送频率规则、导入格式、支持平台、便携数据位置或版本间迁移来源选择。
- 计划任务更新不自动发送测试邮件、立即检查文章或创建新的提醒身份。
- 正式版本号、包装、标签、推送和发布不属于本实施包。

## 安全与停止条件

- 如果 Windows 在使用另一管理员账户确认权限后，无法保证任务仍以原登录用户运行，则停止
  自动提升方案，保留安全提示，不得把任务注册给管理员账户。
- 如果无法在不读取邮件授权码、不暴露个人路径的情况下唯一识别旧任务，则不自动删除。
- 如果更新失败后无法可靠恢复原任务定义，则先实现“同名原位更新且不清理其他任务”，把跨名称
  清理移出 v1.3.3。
- 如果需要改变数据格式、引入常驻系统服务、安装器或全局可写目录，停止实施并重新审阅范围。
- 不以测试通过代替普通用户账户、管理员账户、UAC 取消和真实升级的 Windows 原生验证。

## 验收场景

1. **同一身份正常升级**：旧版提醒已开启，新版位于相邻新文件夹；点击一次，最多出现一次
   Windows 权限确认，应用页面不关闭，最终仍只有一条同名任务并指向新版文件夹。
2. **重复操作**：连续迁移两次、重启新版后再次操作，任务数量、名称和触发器不增加。
3. **普通权限可以更新**：不显示权限确认，直接原位更新并验证。
4. **需要提升权限**：只提升任务小工具；任务主体仍是原登录用户且运行级别为受限。
5. **取消权限确认**：设置、任务、任务标记、授权码和发送记录均保持原状，界面可重试。
6. **旧任务仍在运行**：更新前不会从新文件夹发送邮件；更新成功后旧路径不再被当前身份任务使用。
7. **身份编号变化或多个候选**：不按名称前缀批量删除，不误删另一份便携副本的任务，给出人工处理提示。
8. **旧文件夹已删除或损坏**：能够更新当前同名任务；无法证明归属的其他任务保持不变。
9. **更新或验证中断**：不出现两条都被当作有效的任务，当前设置不被标记为迁移成功。
10. **隐私**：接口、页面、日志和测试输出不出现邮箱、用户名、完整个人路径或授权码。

## 测试要求

- 为任务名称、旧任务引用、权限错误、UAC 取消、更新验证和回滚增加离线单元测试。
- 为成功、无需提升、权限取消、来源不明确和重复迁移增加界面回归测试。
- 扩展 Windows 便携包冒烟测试：用唯一临时任务名称注册两次并改变测试根路径，确认系统中仍为
  一条任务、操作路径已更新、主体权限正确，最后清理临时任务。
- 原生人工测试至少覆盖：普通管理员用户、普通权限启动后同意 UAC、取消 UAC；如果可用，再覆盖
  标准用户输入另一管理员账户凭据。无法覆盖的账户类型必须明确记录。
- 测试只使用临时文件夹、临时任务和临时授权码，不读取个人授权码、不连接真实邮箱、不发送邮件。
- 基础验证：`pnpm lint`、`pnpm build`、`node --test tests/*.test.mjs`、`pnpm test:ui`、
  Windows 最终包原生冒烟测试及空白包隐私检查。
