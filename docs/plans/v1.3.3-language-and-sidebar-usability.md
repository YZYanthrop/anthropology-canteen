## 已经确认

1. 用户会看到什么：“更新健康”“订阅：…成功”“部分失败”“失败来源”。
   为什么不方便：不自然，容易把检查结果理解为添加关注是否成功。
   技术原因：首页完整与精简摘要直接展示查询分类，README 也沿用旧称。
2. 用户会看到什么：关注项向下延伸，短窗口看不到左栏下面内容。
   为什么不方便：不能在左栏单独滚动寻找项目。
   技术原因：左栏采用滚动时停留在顶部的布局，没有可用高度限制和独立纵向滚动区。
3. 用户会看到什么：移除按钮平时不可见，悬停或键盘聚焦后才出现。
   为什么不方便：触摸用户难以发现，点击区域偏小。
   技术原因：按钮默认文字透明、宽度 22 像素，没有无悬停或触摸输入的显示规则。
4. 用户会看到什么：尚无检查结果时可能显示“失败来源：无”，部分来源失败仍提示
   “已检查最新出版记录”。为什么不方便：容易以为全部检查完成。
   技术原因：空结果共用无失败显示逻辑，部分成功共用完成通知。
5. 用户会看到什么：测试通过后仍可能遇到滚动和触摸问题。
   为什么不方便：缺少及时发现这些体验问题的检查。
   技术原因：界面测试使用 jsdom 模拟网页环境，窄屏检查包含样式文本断言；未发现
   大量关注项、短窗口、独立滚动和触摸可见性的专项测试。

## 需要真实浏览器确认

- 大量项目、长名称及折叠分组下，首尾项目、添加入口是否可达。
- 短窗口、布局切换宽度附近及放大后，是否遮挡、裁切焦点或横向溢出。
- 触摸操作是否误触相邻名称；键盘是否能进入、滚动并离开左栏。
- 辅助朗读是否清楚表达区域名称与当前选中项。

本轮未作浏览器实测，不把这些场景写成已复现缺陷。

## 顺序与实施边界

依次实施 Slice A → B → C，每次一个可独立验收的小阶段；前一阶段验证合并后才开始
下一阶段。各建短期 `codex/` 分支，不并行修改首页。实现授权不包含推送和发布。

### Slice A：普通中文与更新情况说明

- 完整右栏、精简摘要及辅助朗读名称统一为“更新情况”。
- 建议分类为“已完成检查”“部分来源暂时无法查询”“本次未能检查”；说明统计单位
  是学者或期刊关注项。关键词组只匹配内容，不作为独立联网检查计数。
- “失败来源”改为“暂时无法查询的数据来源”，保留实际服务名称。
- 区分无关注、尚无结果、正在检查、全部完成、部分完成及全部失败；未检查不得暗示
  一切正常，未尝试的数据来源不得算作失败。
- 说明检查完成不等于有新文章，也不保证数据库完整收录全部成果。
- 分开说明上次成功取得数据的时间、本次检查结果和旧缓存结果；全部失败继续显示
  上次内容，不刷新成功时间。部分完成通知必须说明仍有来源暂时无法查询，可稍后重试。
- 同步相关 README 和新增版本记录，不开展全站重写、不改历史发布事实。
- 只调整显示及必要的页面临时状态，不改变提供方查询、持久数据字段和失败降级规则。

验收：用模拟接口覆盖上述状态，核对两种摘要、通知与辅助朗读的一致性；全部失败保留
旧文章及时间，成功返回零篇文章不误报失败，未尝试来源不误报失败。

### Slice B：桌面左栏独立滚动和短窗口适配

- 按顶栏下方可用高度限制左栏，提供一个明确的纵向滚动区，避免多层嵌套滚动。
- 保持筛选和添加入口可达；极短窗口允许整个左栏滚动或退回正常页面流，不裁切操作。
- 保留长名称、分组折叠、选中状态和操作；窄屏维持正常页面阅读顺序，不照搬桌面限制。
- 滚轮、触控板、键盘均能到达末项；聚焦项目进入可视范围，焦点能正常离开左栏。

验收：少量及至少 100 个混合关注项，包含长名称、空分组和折叠/展开；检查
1440×900、1024×600、1024×400 及宽度 819/820/821 像素附近。
真实浏览器确认左栏独立滚动时正文不随之跳动、首尾均可操作、无新增横向溢出。
极短窗口仍能找到全部入口；样式文本断言仅作辅助。

### Slice C：触摸关注操作与回归测试

- 无悬停能力或粗指针设备明确显示取消关注入口，兼顾同时支持鼠标与触摸的设备。
- 名称统一为“取消关注”，辅助朗读名称包含对象；触摸区域以至少 44×44 CSS 像素为
  设计目标，与名称按钮分开，避免误触。
- 保留鼠标与键盘可发现性；取消聚焦项目后，焦点移到相邻项目或合理分组入口。
- 只取消目标关注，不清除收藏、忽略、已读和翻译；本版不新增取消关注撤销机制。
- 补充大量项目下的准确目标操作、键盘顺序、取消后焦点及触摸可见性回归。

验收：桌面与窄屏触摸均不依赖悬停；模拟接口确认仅取消目标关注且无其他状态清除。
真实浏览器触摸模拟检查计算样式、点击区域和滚动；实际触摸设备验收单独记录，
不得把模拟测试写成已完成真实设备验证。

### Slice D：升级时完整保留邮件提醒

- 自动迁移先选定主数据来源，再只从同一个旧版文件夹读取设置、提醒发送记录和 Windows 加密授权码；不再分别选择来源。
- 迁移前验证实际存在的文件，使用迁移锁、临时文件、目标备份和统一回滚；旧版文件只读，失败不会留下部分替换。
- 当前非空设置、已有授权码和非空发送记录不自动覆盖。已迁移关注但遗漏提醒资料时，只接受身份编号、授权码关联编号、发件地址和认证邮箱完全一致的唯一来源。
- Windows 复制前确认密文可由当前账户解密，仍只保存密文；Mac 保留钥匙串关联方式，不复制或转换 Windows 授权码。
- 提醒状态接口保留 `credentialConfigured`，新增不含敏感内容的 `credentialStatus`，区分已配置、未找到、无法读取和当前环境不支持。
- 自动迁移不发信、不运行检查、不注册后台任务。旧设置显示提醒已开启但当前任务未安装时，明确提示迁移到当前文件夹并复用现有操作。

验收：覆盖首次启动、空白设置、历史遗漏补齐、多个旧版来源、重复读取、损坏文件、写入中断和目标已有新资料；Windows 用临时授权码验证当前账户加密与解密，不读取个人授权码或连接真实邮箱。macOS 钥匙串须在原生环境单独确认。
